### Method Explanation

The problem asks for the probability that a specific pattern $P$ appears as a contiguous substring in a string generated by a random walk on a DAG. We can decompose this problem into two independent concepts: **String Matching** and **Path Counting on a DAG**.

#### 1. String Matching (The Automaton)
To efficiently track whether we have formed the pattern $P$ while traversing the graph, we can use a Prefix Automaton (similar to the one built in the Knuth-Morris-Pratt algorithm). 

Let the length of $P$ be $K$. We can build a state machine with $K + 1$ states, numbered $0$ to $K$.
*   State $j$ ($0 \le j < K$) means that the longest suffix of the string generated so far that matches a prefix of $P$ has length $j$.
*   State $K$ is an absorbing state. Once we reach state $K$, it means $P$ has been found. Any subsequent characters will leave us in state $K$.

We can precompute a transition table $\text{nxt}[j][c]$, which tells us the next state if we are currently in state $j$ and append the character $c$.

#### 2. Total Path Counting
Since we need the exact probability, we first need to know the total number of valid paths from vertex $1$ to any sink vertex. 
Let $W[u]$ be the number of paths from vertex $u$ to a sink. We can compute this using dynamic programming on the DAG in reverse topological order:
*   If $u$ is a sink (out-degree $0$), $W[u] = 1$.
*   Otherwise, $W[u] = \sum_{(u, v) \in E} W[v] \pmod M$.

The total number of possible generated strings is $W[1]$.

#### 3. DP on the DAG (The Core Logic)
Now we combine the graph traversal with the string automaton. We define our DP state as follows:
Let $dp[u][j]$ be the number of valid paths starting from vertex $u$ and ending at any sink, given that our current automaton state is $j$, such that we *eventually* reach state $K$ (meaning $P$ becomes a substring).

We can compute this DP by processing the vertices in reverse topological order.
For a vertex $u$ and a state $j$:
*   **Base Case (Absorbing State):** If $j = K$, the pattern has already been found. Any valid path to a sink is a successful outcome. Therefore, $dp[u][K] = W[u]$.
*   **Base Case (Sink Reached):** If $u$ is a sink and $j < K$, the path ends without finding the pattern. Therefore, $dp[u][j] = 0$.
*   **Transition:** For $j < K$ and non-sink vertex $u$, we iterate over all outgoing edges $(u, v)$. Appending the character $c_v$ transitions our automaton to state $\text{nxt}[j][c_v]$.
    $$dp[u][j] = \sum_{(u, v) \in E} dp[v][\text{nxt}[j][c_v]] \pmod M$$

#### 4. The Final Answer
The walk starts at vertex $1$, which inherently has the character $c_1$. Therefore, our starting automaton state is $j_0 = \text{nxt}[0][c_1]$.
The number of successful paths is $dp[1][j_0]$. 
Since the random walk chooses paths uniformly, the probability is exactly $\frac{dp[1][j_0]}{W[1]}$. We compute this modulo 998244353 by multiplying by the modular inverse of $W[1]$.

### Complexity Analysis

*   **Time Complexity:** 
    *   Building the automaton takes $O(|P| \cdot \Sigma)$, where $\Sigma = 26$ is the alphabet size.
    *   Topological sorting and computing $W[u]$ takes $O(N + M)$.
    *   The main DP processes each edge exactly $|P|$ times. Thus, computing $dp[u][j]$ takes $O((N + M) \cdot |P|)$.
    *   Overall Time Complexity: $O((N + M) \cdot |P|)$.
*   **Space Complexity:**
    *   The DP table requires $O(N \cdot |P|)$ space.
    *   The graph adjacency list takes $O(N + M)$ space.
    *   Overall Space Complexity: $O(N \cdot |P| + M)$.

This easily passes within the 2.0 second time limit for $N \le 10^5$, $M \le 2 \cdot 10^5$, and $|P| \le 20$.
